# 配置文件说明

程序**只读**当前 Windows 用户下的数据目录，不读 `product\`、不读仓库里的模板目录。

```text
%LOCALAPPDATA%\LocalAIHub\
```

在资源管理器地址栏粘贴上面路径回车即可打开。

## 怎么用

1. 先执行任意一条命令（例如 `hub target list --json`），让程序自动生成 `connections.yaml` / `settings.yaml`。
2. 按本文下面的示例改这些文件：填你的 host、user、COM 口。
3. 有源码时，也可以从仓库 `configs\` 把 `*.example.yaml` 拷进去再改，效果相同。

不写 yaml 也能用：直接 `hub run --json user@内网IP -- hostname`，或用已有 `.ssh\config` 里的 Host 名。yaml 只是给常用目标起短名。

**禁止**在任何 yaml 里写密码、token、私钥正文。密码认证：`auth.type: password` 后执行 `hub secret set <目标名>`。

数据目录结构：

```text
%LOCALAPPDATA%\LocalAIHub\
  connections.yaml     必看：SSH / COM 目标
  settings.yaml        可选：内网范围、超时上限等（第一次运行会自动生成）
  recipes\             可选：部署配方，文件名 <名字>.yaml
  ssh\known_hosts      自动维护，一般不要手改
  db\                  自动，任务状态
  logs\                自动，命令输出
  runtime\             自动，hubd 锁文件
```

## 1. connections.yaml（连接目标）

编辑 `%LOCALAPPDATA%\LocalAIHub\connections.yaml`（有源码时可参考仓库 `configs\connections.example.yaml`）。

名字规则：字母开头，可含字母数字 `_` `-`，最长 63。

### SSH 目标

```yaml
targets:
  dev-web:
    transport: ssh
    host: 192.168.1.20          # IP 或主机名
    user: devops
    port: 22                    # 可省略，默认 22
    auth:
      type: ssh-agent           # ssh-agent | private-key | password
    # workspace_root: /opt/app  # 可选；cp 时尽力拦住越界，不是沙箱
```

`auth.type`：

| 值 | 说明 |
|----|------|
| `ssh-agent` | 用本机 OpenSSH 代理（Windows 上常见 `ssh-agent` 服务） |
| `private-key` | 再写 `key_path:` 指向私钥文件（只写路径，不要把钥匙贴进 yaml）。还会尝试 `~/.ssh` 默认身份、本机 ssh-agent，以及已 `hub secret set` 的密码 |
| `password` | 必须先运行 `hub secret set dev-web`，密码进凭据管理器；同时会试 keyboard-interactive |

`key_path` 例：`C:\Users\你的用户名\.ssh\id_ed25519`。`~` 会按用户主目录展开。

`workspace_root` 与命令行 `--workdir`：执行时 Hub 先进入该目录。可以查看其他路径；写入、删除、改权限、重定向到目录外会拒绝。`--workdir` 必须落在 yaml 的 `workspace_root` 之内（若已配置）。

也可以不写 yaml，直接：

```text
hub run --json user@192.168.1.20 -- uname -a
```

或使用 `%USERPROFILE%\.ssh\config` 里的 **精确 Host 名**（不支持通配、Match、多跳跳板）。yaml 里同名目标优先于 ssh_config。

### 串口目标

```yaml
targets:
  board-01:
    transport: serial
    port: COM3
    baud_rate: 115200
    prompt_pattern: ">"
```

`port` 必须是字符串（如 `COM3`），不能写成数字。临时口也可以直接 `hub serial exec COM3 ...`（可用 `--baud`）。

## 2. settings.yaml（全局行为）

编辑 `%LOCALAPPDATA%\LocalAIHub\settings.yaml`（有源码时可参考仓库 `configs\settings.example.yaml`）。

不建这个文件也能用，第一次运行会按下面默认值生成。

| 字段 | 默认 | 含义 |
|------|------|------|
| `network.scope` | `intranet` | `intranet`：只允许内网（RFC1918、本机、链路本地等）。`all`：允许公网 |
| `ssh.host_key` | `accept-new-intranet` | 内网未知指纹第一次自动收下；**已记录的指纹一旦变化就拒绝** |
| `daemon.idle_exit` | `0` | `0` 表示 `hubd` 不因空闲退出 |
| `connection.idle_timeout` | `30m` | SSH 空闲多久后回收连接 |
| `limits.max_response_bytes` | 8388608 | `--json` 里 stdout/stderr 截断上限（字节） |
| `limits.max_concurrent_jobs` | 32 | 同时跑的任务数 |
| `log.retain_days` | 30 | 日志保留天数 |

改 yaml **不会**立刻改已经建好的 SSH 连接；新任务会用新配置，旧连接空闲超时后按新配置再建。

多写了未知字段会被拒绝（`CONFIG_INVALID`），避免拼错却静默走默认。

公网：单次命令加 `--allow-public`，或把 `network.scope` 改成 `all`。

## 3. recipes（部署配方）

仅 `hub deploy` 需要。在 `%LOCALAPPDATA%\LocalAIHub\recipes\` 下建 `<名字>.yaml`（有源码时可参考仓库 `configs\recipes\`）。

示例 `artifact-service.yaml`：

```yaml
name: artifact-service
precheck:
  - "test -d /opt/app"
upload:
  remote_dir: /opt/app
  remote_name: app.tar.gz
apply:
  - "tar -xzf /opt/app/app.tar.gz -C /opt/app"
  - "systemctl restart myapp"
verify:
  type: command
  command: "systemctl is-active myapp"
  timeout: 30s
rollback:
  - "systemctl restart myapp"
```

然后：

```text
hub deploy --json 目标名 --recipe artifact-service --artifact .\app.tar.gz
```

`--recipe` 填文件名（不含 `.yaml`）。未知字段会拒绝。

`verify.type` 只能是 `command`，并且在 **SSH 远端**执行，不会从 Windows 去探测 HTTP。

命令字符串原样发送，没有占位符替换。回滚只跑配方里写的 `rollback` 命令。

可选 `--idempotency-key`：同一目标 + 配方 + 键且内容没变时不会重复 apply。

---

## 4. 建议操作顺序

1. 确认 `hub.exe`、`hubd.exe` 在同一文件夹。
2. 能直连则先试：`hub run --json user@内网IP -- hostname`。
3. 常用机器写入 `connections.yaml`，用短名调用。
4. 需要密码时：yaml 里 `auth.type: password`，再 `hub secret set 短名`。
5. 要发布时再准备 `recipes\` 和制品文件。

本机 OpenSSH 配置仍可继续用；Hub 不会读取你 yaml 或钥匙文件里的密码正文写入日志。
