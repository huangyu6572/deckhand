# 03 hub cp

SFTP。串口 → `CAPABILITY_UNSUPPORTED`。V1：**单文件**，不递归、不保留权限/mtime。覆盖已存在远端文件：允许。`workspace_root` 为**尽力**拦截，不是安全沙箱（SFTP 无可靠 `openat`）。

## 路径

远端侧必须是 **已解析 target 名 + 冒号**（`dev-web:/tmp/a`），不是「看见冒号就是远端」。

- Windows `C:\foo`、`C:/foo` 一律本地。
- IPv6 直连不用 `user@[fd00::1]:/tmp/a` 这种 cp 语法；先在 yaml 写别名再 `alias:/tmp/a`。

本地相对路径相对调用时 cwd。下载：本地临时文件 → 校验已传输字节流哈希 → 原子 rename。上传：远端 `.hubtmp-*` → 对**已发送字节**做 SHA-256（不承诺远端独立 hash API）→ rename。不能证明 rename 前磁盘未被其它进程改写。

## 输入

```text
hub cp [flags] <src> <dst>
```

IPC `File.Copy`：`src`，`dst`，`timeout_ms`，`allow_public`。

## 输出

`direction`、`bytes`、`sha256`（发送流哈希）、`remote_path`、`local_path`。

## 测试

| ID | 期望 |
|----|------|
| C-01 | 上传成功，无最终名半成品 |
| C-02 | 中断 → 无最终名或仅 `.hubtmp-*` |
| C-03 | workspace 外 → `FILE_OUTSIDE_WORKSPACE` |
| C-04 | 下载成功，本地原子替换 |
| C-05 | COM → `CAPABILITY_UNSUPPORTED` |
| C-06 | `hub cp --json a b` 退出 2 |
| C-07 | 流哈希不符 → `FILE_CHANGED` |
| C-08 | `hub cp --json C:\tmp\a t:/tmp/a` 识别为上传不是非法双远端 |
